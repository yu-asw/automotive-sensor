## 0. 먼저, 왜 2명이 유리한가

이 과목은 원래 20명 기준으로 설계되어 있었다. 그 계획에서 여러분은 4명이 보드 한 대를 나눠 쓰고, 대부분의 시간을 **옆 사람이 실습하는 것을 지켜보며** 보냈을 것이다. 2명이면 다음이 가능해진다.

| | 20명 편성 | **2명 편성 (이 계획)** |
|---|---|---|
| 장비 | 조당 1세트를 4명이 공유 | **1인 1세트 + 프로젝트 차량 1대 전용** |
| 레이더 실습 | HB100 도플러 모듈까지. 차량용 FMCW 레이더는 교수 시연만 | **TI IWR6843 mmWave 레이더 실물 실습** (20명 예산으로는 불가능) |
| 결과물 | 개인 과제 리포트 4편 | **실제로 굴러가는 자율주행 차량 1대 + 본인 담당 서브시스템** |
| 피드백 | 학기당 몇 번 | **매주 대면 랩미팅, 랩노트 전량 첨삭** |
| 난이도 | 전원이 따라올 수 있는 수준으로 하향 | **막히면 그 자리에서 같이 뚫는다는 전제로 상향** |

대신 조건이 하나 붙는다. **2명이므로 숨을 곳이 없다.** 매주 무엇을 했는지 기록하고 설명해야 하며, 한 명이 멈추면 프로젝트 전체가 멈춘다. 이 계획서는 그 전제 위에 쓰였다.

## 1. 과목이 다루는 것

자율주행과 ADAS는 사람의 눈을 대신하는 **센서**에서 출발한다. 이 과목은 차량 환경인식 센서 6종 — **카메라, 초음파, 레이더, 라이다, GNSS, IMU** — 의 동작 원리, 사양(스펙) 해석, 인터페이스와 데이터 취득 방법을 다룬다.

경계는 분명하다. 이 과목은 **"센서가 어떤 물리 원리로 세상을 측정하고, 그 데이터가 어떤 형태로 소프트웨어에 도달하는가"** 까지다. 그 데이터를 처리하는 알고리즘은 후속 과목의 몫이다.

| 내용 | 담당 과목 |
|---|---|
| 센서 원리 · 사양 · 인터페이스 · 데이터 취득 | **자동차센서 (이 과목, 3-2)** |
| CNN/RNN 등 학습 알고리즘 | 딥러닝 (3-2, 병행 권장) |
| 2D 영상·3D 포인트클라우드 신호처리, 객체인식 | 자동차비전 (4-1) |
| 센서퓨전 심화, 항법·환경인식·제어 | 자율주행 (4-2) |

### 이수 후 할 수 있게 되는 것

1. 6종 센서의 동작 원리를 물리 수준에서 설명하고, 데이터시트의 주요 사양(해상도·FOV·분해능·검출거리)을 해석한다.
2. 임베디드 보드(TOPST D3-G)에서 GPIO·I2C·UART·MIPI-CSI/V4L2·GStreamer로 **센서를 직접 연결하고 데이터를 취득한다.**
3. 카메라 캘리브레이션을 수행하고 내부/외부 파라미터와 왜곡 모델을 설명한다.
4. 실차 공개 데이터셋(KITTI, nuScenes)의 카메라·라이다·레이더 데이터를 읽고 시각화·기초 분석한다.
5. 센서별 강점·한계(조도·날씨·거리·해상도)를 비교하고 센서퓨전이 필요한 이유를 설명한다.
6. **여러 센서를 하나의 실시간 시스템으로 통합하고, 그것이 움직이는 차량 위에서 동작하게 만든다.** ← 2명 편성에서 추가된 목표

## 2. 학기 프로젝트: 센서 통합 자율주행 미니카

### 2-1. 플랫폼

**TOPST D3-G**(텔레칩스 TCC8050, 국산 차량용 반도체) + **PiRacer 섀시** 기반의 1/10 스케일 자율주행 차량 **1대를 두 사람이 공동으로 구축**한다.
소프트웨어는 Ubuntu 22.04 + **ROS2 Humble**. 센서마다 ROS2 노드를 만들고 토픽으로 데이터를 주고받는 구조로, 실제 자율주행 소프트웨어 스택과 같은 방식이다.

> 참고: 이 플랫폼(D-Racer)은 2026 SEA:ME 해커톤(폭스바겐그룹코리아 후원, 국민대 주관)의 공식 플랫폼이다. 학기 결과물을 그대로 대회 출전이나 캡스톤디자인으로 이어갈 수 있다.

**진행 순서는 "차를 먼저 굴리고, 센서를 하나씩 얹는다"이다.** 기초 이론 2주 → 카메라로 차를 굴린다(3~6주) → 라이다를 얹는다(7~9주) → 레이더를 얹는다(10~12주) → 통합(13~15주). 센서를 하나 얹을 때마다 **원리 → 연결·취득 → 차량 기능화 → 시연·기록** 네 단계를 반복한다.

### 2-2. 최종 시연 시나리오 (15주차)

실내 트랙에서 차량이 다음을 수행한다.

1. **카메라 차선 인식 자율 주행** — 트랙 1바퀴 완주
2. **전방 장애물 감지 후 정지/회피** — 초음파 + 2D 라이다 (AEB·긴급제동의 축소판)
3. **접근 물체 속도 측정** — HB100 도플러 레이더
4. **주행 궤적 로깅** — GNSS + IMU, 사후 시각화
5. **6종 센서 데이터 실시간 통합 표시** — ROS2 토픽 + 대시보드

### 2-3. 역할 분담

공동 플랫폼 1대에 대해 각자 **담당 서브시스템**을 갖는다. 담당은 "프로젝트에서 책임지는 범위"이지, **배우는 범위가 아니다.** 이론 수업과 중간시험은 6종 센서 전체를 대상으로 하며, 두 사람 모두 전 센서를 학습한다.

| | **학생 A — 인지·비전 (Perception / Vision)** | **학생 B — 측거·측위 (Ranging / Localization)** |
|---|---|---|
| 담당 센서 | MIPI-CSI 카메라, USB 웹캠 | 초음파, 도플러 레이더, 2D 라이다, GNSS, IMU |
| 주요 작업 | V4L2/GStreamer 영상 파이프라인, 카메라 캘리브레이션, 차선 검출(Canny+Hough), 조향각 산출 | GPIO ToF 거리 측정, 도플러 속도 산출, 라이다 스캔·장애물 클러스터링, NMEA 파싱, I2C IMU, 1D 칼만필터 |
| 산출 ROS2 토픽 | `/camera/image_raw`, `/lane/steering_angle` | `/ultrasonic/range`, `/scan`, `/radar/speed`, `/gps/fix`, `/imu/data` |
| 공통 담당 | 시스템 아키텍처 설계, 차량 제어(모터·서보) 노드, 통합, 대시보드, 최종 시연 | ← 좌동 |

**상호 교육이 평가 항목이다.** 매주 랩미팅에서 각자 자기 담당 진행을 상대에게 설명하고, 8주차 직전과 14주차에 **상대 담당 센서에 대한 구술 확인**을 받는다. 2명뿐이므로 서로가 서로의 유일한 청중이자 검증자다.

### 2-4. 마일스톤 (4회)

| | 시점 | 합격 기준 |
|---|---|---|
| **M1 — 플랫폼 기동** | 4주 말 | D3-G 부팅 + ROS2 노드 간 통신 확인, 모터·서보 원격 제어로 직선 3 m 주행, CSI 카메라 영상 스트리밍 확인 |
| **M2 — 카메라 자율주행** | 6주 말 | 차선 검출 기반으로 트랙(직선+완만한 곡선) 1바퀴 자율 주행, 전방 30 cm 내 초음파 감지 시 정지 |
| **M3 — 라이다 통합** | 9주 말 | 2D 라이다로 전방 장애물의 거리·각도 검출 후 **정지가 아닌 감속 또는 회피** 동작, 카메라 주행과 충돌 없이 동작 |
| **M4 — 레이더 통합** | 12주 말 | 도플러 속도 측정 로그 확보, 접근 물체 경고 동작, 카메라·라이다·레이더 토픽 동시 발행 |

최종 시연(15주)은 여기에 초음파·IMU까지 더한 **6종 센서 동시 발행 + 주행 로그(rosbag) + 대시보드**의 통합 상태를 기준으로 한다.

> **마일스톤은 성공/실패로 채점하지 않는다.** 도달하려고 한 과정과 그 기록으로 평가한다. 실패한 시도라도 랩노트에 원인 분석과 다음 가설이 남아 있으면 만점이 가능하다. 하드웨어 프로젝트는 원래 절반이 실패다. 감추지 말고 기록할 것.

## 3. 수업 운영 방식

### 주 3시간 구성

| 시간 | 내용 |
|---|---|
| 0:00–1:30 | **강의 90분** — 랩미팅 10분(각자 지난주 진행·막힌 곳·이번 주 계획 브리핑) + 해당 주차 센서의 원리·사양·인터페이스 (공통) |
| 1:30–3:00 | **실습 90분** — 그 주의 센서를 연결 → 데이터 취득 → 차량 기능으로 통합. 교수 상주, 막히면 그 자리에서 함께 해결 |

### 주간 랩노트 (매주 제출, 평가 20%)

GitHub 저장소에 **매주 Markdown으로 커밋**한다. 분량보다 성실성과 구체성으로 평가한다.

1. **이론 요약** — 이번 주 배운 것 3~5줄, 이해 안 된 것 명시
2. **진행 기록** — 한 것 / 막힌 것 / 시도한 해결책 / 다음 주 계획
3. **증거** — 측정 데이터, 그래프, 스크린샷, 오실로스코프 캡처, 실패 로그
4. **소스 코드** — 같은 저장소에 커밋

이 저장소가 학기 말에 그대로 **포트폴리오**가 된다. 채용·대학원·해커톤에서 "무엇을 만들었는가"를 증명하는 것은 성적표가 아니라 이 기록이다.

### 데이터셋 랩 (수업 내 실습)

프로젝트 차량은 저가 센서를 쓴다. 차량급 센서(3D 라이다, 77 GHz 레이더)의 실제 데이터는 **공개 실차 데이터셋으로 별도 경험**한다. 8주차 KITTI 라이다 포인트클라우드, 11주차 nuScenes 레이더 실습이 여기에 해당한다. 개인 노트북(Colab 가능)으로 수행한다.

| **프로젝트** | **50%** | 마일스톤 4회 20% (각 5%) + 최종 시연 20% + 최종 보고서 10% |
| **주간 랩노트** | **20%** | 매주 제출 (14회). 미제출 1회당 감점 |
| **중간 이론 점검** | **20%** | 8주차 강의 앞 30분 필기, 1~7주 이론 범위 |
| **참여·상호교육** | **10%** | 랩미팅 브리핑 성실도, 상대 담당 센서 구술 확인(8주·14주) |

기말시험은 시행하지 않고 **최종 시연·발표·보고서로 대체**한다.

**최종 보고서**는 개인별 제출이며, 다음을 포함한다 — ① 시스템 전체 아키텍처 ② **본인 담당 서브시스템**의 센서 원리·사양·구현·측정 결과 ③ 실패와 원인 분석 ④ 센서별 한계 비교와 센서퓨전 필요성에 대한 본인의 결론 ⑤ 개선 방향.

## 8. 첫 2주 안에 갖춰야 할 것

1강 실습에서 개발 PC를 셋업하고, 2강에서 D3-G를 켠다. **그 전까지 아래가 갖춰져 있어야 3주차부터 카메라를 붙일 수 있다.**

### 8-1. 병행 과목

| | 과목 | 비고 |
|---|---|---|
| 이미 이수했다면 유리 | MCU프로그래밍 (2-2), 신호및선형시스템 (2-2) | GPIO·I2C·UART 경험과 주파수 개념이 있으면 3주 정도 앞서 출발한다 |
| **병행 강력 권장** | **임베디드시스템 (3-2)** | 라즈베리파이·리눅스를 다룬다. 이 과목의 D3-G 작업과 직접 연결된다 |
| 병행 권장 | 딥러닝 (3-2) | 5주차 영상처리, 8·11주차 데이터셋 실습과 맞물린다 |

### 8-2. 자율 준비 (1강 실습에서 시작, 2강 전까지)

우선순위 순이며, **1~3번은 2강 전까지 반드시** 해 둘 것.

1. **Python** — numpy 배열 다루기, matplotlib 그래프. 문법을 외우기보다 "데이터를 읽어서 그림으로 그려보는 것"까지 가면 충분하다.
2. **Linux 명령줄** — `cd` `ls` `apt` `ssh` `vim`(또는 nano), 파일 권한. 학기 내내 보드에 SSH로 붙어서 작업한다.
3. **Git / GitHub** — `clone` `add` `commit` `push`, 브랜치 개념. 랩노트와 코드를 여기에 올린다.
4. **OpenCV 맛보기** — 이미지 읽기, 그레이스케일 변환, Canny 엣지. 공식 튜토리얼 앞부분이면 된다.
5. **ROS2 Humble 튜토리얼** — 공식 문서의 노드·토픽 파트만. 여유가 되면.

### 8-3. 미리 생각해 둘 것

1강 실습에서 **역할(A: 비전 / B: 측거·측위)을 논의하고 2강에 확정**한다. 어느 쪽에 끌리는지, 왜 그런지 생각해 두면 좋다. 둘 다 하고 싶으면 그것도 좋은 답이다 — 학기 후반에 서로의 코드를 건드리게 되어 있다.
